# 个人术语表与用户词库译文

给用户自己领域的词（对齐、词库、候选框、C盘 这类）一个可维护的家，并让这些词在候选窗里有译文。
2026-10-23 用户定的四个方向之一、之二：**个人术语表**与**用户词库的译文生成**。

## 现状（2026-10-23）

| 已有 | 落点 | 缺什么 |
|---|---|---|
| 自动学的用户词 | `user-words.tsv` | 不能手增删、不能标优先级 |
| 个人释义表 | `user-glossary-<语言>.tsv`（可手改） | 没有界面，只能找到文件改；只有「上屏后发现随包表没有」才写 |
| 导入词库 | 用户目录 `dicts/`，词库页开关 / 移除 | 粒度是整本库，不是一条术语 |
| 自定义短语 | 设置「自定义短语」页 | 编码 → 短语，不参与候选排序 |

引擎侧 `all_dictionaries()` = 内置 → 附加词库 → 用户词（`crates/qingjian-core/src/engine/setup.rs`），
排序只看词频，**没有「用户显式标注」这一档**。释义兜底（`CloudGlossFiller`）只在词上屏后补、且要求云联想开着。

## 已定的决定（2026-10-23）

1. **术语只参与排序**，不置顶压过内置词（不加「必在第一」的特权位）。
2. **译文生成走云**，语言：英 / 日 / 西 / **法** / **韩**（法语、韩语新增；德语已有，保留）。
3. 要能**查看与勘误**：GUI 或 WebUI 均可。
4. 本期范围是「给用户词库里的词生成日常译文」；「输入中文直接出英文句子」另立下一阶段研究。
5. 候选质量的尺子先拆成**覆盖**与**排序**两个缺口（已在 `--eval-text` 落地，见 `docs/plan/model-eval.md`）。
6. 界面形态（2026-10-23 评审过草图）：**独立「术语」页**、**生成 → 待确认 → 确认** 一道闸、标签用固定 7 个。


## 使用场景与标签（2026-10-23 用户提供）

使用者做**商业地产施工管理**，日常要打的是这些领域，术语表与领域词库都按这个优先级排：

| 标签 | 覆盖内容 | 现状 |
|---|---|---|
| 工程施工 | 总包 / 分包 / 甲供材 / 认质认价 / 消防验收 / 竣工备案 / 人防 | 无随包词库 |
| 项目管理 | 里程碑 / 甘特 / 变更签证 / 索赔 / 例会纪要 / 巡检 | 无随包词库 |
| 建筑设计 | 幕墙 / 泛光 / 客流 / 动线 / 净高 / 荷载 / 二装 | 无随包词库 |
| 机电 | 综合支吊架 / 桥架 / 风管 / 末端 / 冷站 / 强弱电 | 无随包词库 |
| 商业品牌 | 主力店 / 次主力 / 租金坪效 / 招商 / 业态配比 | 无随包词库 |
| 二次元 / IT | 番剧 / 同人 / 声优 / 服务器 / 部署 / 容器 | IT 有随包词库；二次元无 |

**结论：随包 11 本领域词库里一本都不覆盖前五个领域**（现有是法律 / 医学 / 地名 / 成语 / 诗词 / 动物 / 汽车 / 金融 / 食物 / IT / 历史人物）。
所以顺序是「先有术语表 → 攒到几百条 → 再打包成随包词库」，不反过来等数据源。二次元不建议引萌娘百科一类
（CC BY-NC-SA 的 NC 与商用冲突），靠个人术语表 + 语料挖词。

数据源可行性调研记在 `docs/notes/domain-lexicon-sources.md`（2026-10-23）：**五个工作领域没有可随包的干净词表**
（术语在线明文禁转载、国标正文受著作权），可用的是 Wikidata / 维基（品牌与二次元）+ 政府公文语料挖词 +
自建 300–800 条核心术语。

## 新增一门学习语言的改动面（法 / 韩各一遍）

以韩语为例，一共八处，缺一处就会出现「能选但不显示」或「能生成但加载不了」：

| # | 位置 | 内容 |
|---|---|---|
| 1 | `crates/qingjian-core/src/candidate/language.rs` | `Language::Korean`、`code() = "ko"`、`FromStr`、单测 |
| 2 | `crates/qingjian-predict/src/gloss/prompt.rs` | 韩语系统提示词 + `clean_text` 的**谚文**校验（像德语那样判字符集与长度）+ 解析单测 |
| 3 | `tools/gloss-gen/src/prompt.rs` | `GlossLanguages` 加 `ko`（结构体、`parse`、`all`、`label`、`system_prompt` 分支）+ 全量提示词里加一节 |
| 4 | `tools/gloss-gen/src/args.rs` | `--languages` 的说明文字（en / ja / vi / de / fr / ko） |
| 5 | `apps/settings/src/view/parts/controls.rs` | `LANGUAGES` 数组（现在的 6 项 → 8 项） |
| 6 | 三个壳的语言列表与界面名 | `apps/macos/src/host/mod.rs`、`apps/windows/server/src/assembly/mod.rs`、`apps/linux/server/src/assembly/mod.rs`、`apps/macos/src/preferences/controls.rs`、`apps/windows/settings/src/panel/pages/usage.rs`、`apps/settings/src/stats/mod.rs` |
| 7 | `assets/glossary/glossary-ko.tsv` | `gloss-gen` 全量生成（约 24 万词、十几分钟到一小时，费用与德/西同一档） |
| 8 | 等级表（可选） | 法语 CEFR、韩语 TOPIK；许可没核之前不做，`assets/levels/README.md` 里记一笔 |

**韩语特有的两条**：译词用谚文、动词给 `-다` 原形；汉字词与固有词都收，但同义词按常用度只留两条（与日语同一策略）。

## 数据来源与权威（2026-10-23 定：方案 A）

**唯一权威是统一术语表**（本机 `data/terms/unified.tsv`，13 列：词 / 读音 / 标签 / 进拼音候选 / 英文 /
其他译法 / 备注 / 来源 / 录入日期 / 日 / 西 / 法 / 韩）。

| 来源 | 角色 |
|---|---|
| `data/terms/unified.tsv` | **唯一权威**。术语页做好后由输入法读写用户目录的 `user-terms.tsv`，它是这份表的运行时形态 |
| `D:\...\personnel\glossary`（用户原来的术语库） | 转为**历史来源留档**，不再手工维护；合并脚本读它一次 |
| `data/terms/pdf/pairs-raw.tsv`（Gucci 进度计划） | 中英对照来源，只在本机做译名参考 |
| 术语在线逐词查询结果 | 只做交叉校验，标「待核」 |

- 合并脚本：`.toolchain/merge_terms.py`（本机，不进仓库）；读音由 `pypinyin` 整词判断（装在 `data/pylib`，
  与自带词库重合的 117 条读音**零冲突**），缺读音的只在「不进拼音候选」的商务沟通条目上。
- 新增术语的入口：术语页（写好之后）→ `user-terms.tsv`；过渡期直接改 `unified.tsv` 并跑一次合并脚本。
- 不进仓库、不进发布包：`data/` 已 gitignore；发布物里的领域词库是另一条路（自建核心表审核后再打包）。


## 候选窗注解规则

- 术语命中的候选，注解优先用**个人译文**（`PersonalGlossary` 那一层已经在随包表之上）。
- 术语还没生成译文时不占位、不显示「生成中」，与普通候选一致。
- 多个术语命中同一页时各自注解，不合并。

## 术语表

- 文件：用户数据目录 `user-terms.tsv`（macOS / Linux 各自的用户目录，Windows 是 `%APPDATA%\Qingjian\`），
  13 列 `词 ⇥ 读音 ⇥ 标签 ⇥ 进拼音候选 ⇥ 英文 ⇥ 其他译法 ⇥ 备注 ⇥ 来源 ⇥ 录入日期 ⇥ 日 ⇥ 西 ⇥ 法 ⇥ 韩`；
  输入法只用前四列，其余是给人看的。
- **装配（2026-10-23 已实现）**：`qingjian-platform` 的 `terms` 模块把它转成一本附加词库
  （词频 [`TERM_BOOST`] = 50,000），由 `extra_dictionaries::load` 在 `dicts/` 的上一级找到文件后追加，
  三个壳与热加载都自动带上，不需要改壳。只收「进拼音候选 = Y 且标了读音」的条目，坏行跳过。
- **加成是词库词频，不是置顶**：实测 30 条样本（`--extra-dict` 实验）首选 15 → 28、前三 17 → 30、
  落到九名外 13 → 0；5 万与 20 万词频效果相同，取 5 万。没有做「必在第一」的特权位（用户定：只参与排序）。
- 删除术语**不动学习数据**；另有一张**屏蔽表**（`user-blocked.tsv`），防止删掉的词被自动学习又加回来（未做）。
- 读音：本机用 `pypinyin` 整词判断生成（与自带词库重合的 117 条零冲突）；产品侧以后走
  `dict-convert lexicon` 的多音字输出 → `gloss-gen pinyin`，与词库同一套。

## 译文生成

- **触发**：术语 / 用户词 / 导入词库有新增或变更时，后台批量入队；沿用 `tools/gloss-gen` 的提示词与
  `CloudGlossFiller` 的批量与去重（1.5 s / 8 词一批），结果写 `user-glossary-<语言>.tsv`。
- **状态机**：`待生成 → 已生成（待确认）→ 已确认 / 已修改`。待确认的先进 `user-glossary-pending-<语言>.tsv`，
  界面里可改可删，确认后才进正式表。理由：自动生成的错译直接进正式表会长期显示在候选窗里，且难发现。
- **限流与用量**：与 Phase 6 的「请求量控制」共用一个实现（按分钟限流、本月请求数），只发词面，不发上下文。
- **失败重试**：同一词最多重试 3 次，仍失败标 `失败` 留在待生成队列，界面可见。
- **法语**：需要动五处——`Language::French`、`tools/gloss-gen` 的语言枚举与提示词、`assets/glossary/glossary-fr.tsv`、
  设置「语言」页选项、`PersonalGlossary` 的文件名（自动按 `code()` 走）。等级表（CEFR）本期不做。

## 界面

- **推荐**：设置程序新增「术语」页（`apps/settings`，bamboo-slip 现有控件够用：分组行、输入框、列表、对话框）。
  内容：搜索、一行一词批量粘贴添加、改读音 / 标签、删除、导出 / 导入 TSV、逐条「生成译文」与待确认列表。
  批量勘误先靠「导出 TSV → 改 → 导入」，不做表格控件。
- **备选**：本地 WebUI（127.0.0.1 + 一次性 token）。只在批量勘误确实成为瓶颈时再做，不常驻、不随包。
  理由：三平台已共用一份 `apps/settings`，WebUI 要引入 HTTP 服务与前端资源，产品化与安全面都更大。
- 三平台同步：macOS 装在 `Qingjian.app/Contents/Applications/`，Windows 与 Server 同目录，Linux `<前缀>/bin`。

## 验收

- Core：术语命中（全拼 / 简拼 / 双拼 / 形码）、排序加成、删除不动学习、屏蔽生效、TSV 坏行跳过——单测。
- 设置页：`config_keys` 离屏点遍、读写核对；术语增删改查各一条端到端。
- 性能：术语表 1000 条时 `--typing` 逐键延迟不变；`--replay` 在冻结日志上不退化。
- 译文：生成后候选窗显示；待确认表可改可删；本月请求数可见。

## 不做

- 术语置顶特权位、按应用分组、跨设备同步、离线生成、术语/词库市场。
- 自动把「用户词」升格成术语（保持两类数据分开，避免自动学习的噪声进术语表）。
